# [퍼즐액션,고난도] 백만 번 죽는 네모 (가제) 게임 기획서 — PC(Steam)

작성일: 2026-10-10 · 기획: 민수님

**한 줄 요약:** 표정 있는 작은 네모를 움직여 장애물을 피해 동전을 모으고 골인하는 고난도 퍼즐액션 게임이다. 캠페인으로 실력을 쌓은 뒤에는 **내가 만든 지옥 같은 맵을 친구에게 던져 주고, 같이 방에 모여 도전**한다.

이 문서는 **PC(Steam)판** 기획서다. 게임 규칙, 캠페인, 에디터, 아트는 두 판이 같으며 이 문서를 기준으로 한다. 모바일판(토스 미니게임)은 별도 기획서에서 달라지는 부분만 다룬다.

**이 게임의 재미 3가지**

1. **죽으면서 배우는 재미** — 조작은 이동뿐인데, 패턴을 익히면 불가능해 보이던 맵이 뚫린다.
2. **만들어 괴롭히는 재미** — 내가 만든 맵에서 친구가 수십 번 죽는 걸 보는 재미.
3. **같이 죽는 재미** — 3~4명이 같은 맵을 동시에 달리며 서로 죽는 모습에 웃는다.

**레퍼런스 핵심:** "세상에서 가장 어려운 게임"은 2008년 플래시 게임으로, 방향키만으로 빨간 사각형을 움직여 동전을 모두 모으고 초록 골인 지점에 도착한다. 파란 공에 닿으면 죽고, **점수는 죽은 횟수**다. 조작은 단순하고 맵이 전부라서, 유저가 맵을 만들어 공유하는 구조와 잘 맞는다.

## 2. 게임 구조

세 모드는 따로 노는 것이 아니라 하나의 고리로 이어진다.

```
┌────────┐   ┌────────┐   ┌════════┐   ┌────────┐
│ 캠페인  │ → │ 에디터  │ → ║직접 클리어║ → │ 맵 코드  │
│장치 배움 │   │칸+경로  │   ║깬 맵만 업로드║  │ 친구에게  │
└────────┘   └────────┘   └════════┘   └────────┘
                  ▲                        │
       반응 보고 │                  같이 ┌──┴──┐ 혼자
        다음 맵  │                       ▼     ▼
             ┌────────┐   ┌────────┐   ┌────────┐
             │후기·기록 │ ← │ 멀티방  │   │혼자 도전 │
             │좋아요,클리어율│  │3~4명 동시│   │최소 데스  │
             └────────┘   └────────┘   └────────┘
                  ▲                          │
                  └──────────────────────────┘
```

캠페인에서 배운 장치로 맵을 만들고, 직접 깬 맵만 코드로 공유된다. 친구가 혼자 또는 멀티방에서 도전하고, 남긴 후기와 죽은 횟수가 다음 맵을 만들 동기가 된다. PC판은 서버 없이도 Steam 기능으로 이 고리를 거의 그대로 유지한다.

## 3. 테마와 아트: 리소스 최소화

**도형과 색, 효과만으로 매력을 만든다.** 원작도 빨간 사각형과 파란 공이 전부였다. 여기에 표정과 타격감을 더해, 그림은 적게 그리면서도 아기자기하고 통쾌하게 보이게 한다.

### 3.1 캐릭터: 표정 있는 네모

| 대상 | 모양 | 매력 포인트 |
| --- | --- | --- |
| 플레이어 | 눈 두 개만 있는 네모 | 이동 방향을 눈이 따라봄. 장애물이 가까우면 눈이 커지고 떨림 |
| 장애물 | 화난 눈썹이 동그라미 | 움직이는 방향으로 눈을 흘김 |
| 동전 | 반짝이는 작은 동그라미 | 먹을 때 톡 튀는 소리와 효과 |
| 골인 | 빛나는 문 | 도착하면 네모가 만세 |

표정은 **눈 모양 몇 가지를 코드로 바꾸는 것만으로** 만든다. 프레임 애니메이션을 그리지 않는다.

### 3.2 죽음 연출이 곧 매력

이 게임에서 플레이어는 수백 번 죽는다. 그래서 죽음을 **웃기고 짧게** 만든다.

- 네모가 작은 조각들로 펑 터지고, 화면이 살짝 흔들림 (파티클 1종으로 처리)
- 화면 구석 데스 카운터가 크게 올라감
- 0.3초 만에 체크포인트에서 다시 시작. 기다림이 없어야 "한 번만 더"가 된다

### 3.3 월드 테마 = 색 팔레트 교체

월드마다 그림을 새로 그리지 않고 **색 팔레트만 바꾼다.** 같은 도형이 월드 1에서는 파스텔, 월드 5에서는 어두운 네온으로 보인다. 유저도 에디터에서 팔레트를 골라 맵 분위기를 바꿀 수 있다.

### 3.4 리소스를 매력으로 바꾸는 수단

| 수단 | 비용 | 효과 |
| --- | --- | --- |
| 색 팔레트 | 매우 낮음 | 월드·맵마다 다른 분위기 |
| 눈 표정 | 낮음 | 도형에 성격이 생김 |
| 늘어났다 줄어드는 움직임 | 코드로 처리 | 출발·멈추기·부딪히기에 타격감 |
| 파티클·화면 흔들림 | 낮음 | 죽음과 동전 획득이 시원함 |
| 사운드 | 보통 | 가장 큰 만족감. 효과음에 더 투자한다 |

## 4. 기본 모드: 싱글 캠페인

| 항목 | 내용 |
| --- | --- |
| 목표 | 동전을 모두 모으고 골인 |
| 조작 | 이동만 (점프·공격 없음). 속도는 항상 일정 |
| 구성 | 월드 5개 × 스테이지 10개 = 50개 |
| 기록 | 죽은 횟수, 클리어 시간. **0데스 클리어**는 별도 표시 |
| 체크포인트 | 초반 월드는 넉넉하게, 후반 월드는 점점 줄임. 체크포인트에서 먹은 동전은 저장됨 |
| 해금 | 월드의 스테이지 7개를 깨면 다음 월드 열림 (막히는 스테이지가 있어도 진행 가능) |

### 4.1 월드별 새 장치

월드마다 장치를 하나씩 소개하고, 그 월드 안에서 점점 어렵게 쓴다.

| 월드 | 새 장치 | 색 팔레트 (예시) |
| --- | --- | --- |
| 1 | 왕복하는 장애물 | 파스텔 |
| 2 | 원을 그리며 도는 장애물 | 노을 |
| 3 | 열쇠와 문 | 숲 |
| 4 | 얼음 바닥(미끄러짐), 컨베이어 | 겨울 |
| 5 | 사라졌다 나타나는 바닥, 전부 섞은 최종 월드 | 네온 |

**캠페인은 에디터 튜토리얼이기도 하다.** 캠페인에서 만난 장치를 에디터에서 그대로 쓸 수 있고, 월드를 깨면 그 장치가 에디터에 해금된다. "나도 이런 맵을 만들 수 있겠다"는 생각이 자연스럽게 들게 한다.

### 4.2 원작을 그대로 가져오는 것과 바꾸는 것

| 그대로 | 바꿈 |
| --- | --- |
| 이동만 하는 단순한 조작 | 죽음 연출을 웃기고 빠르게 (0.3초 만에 재시작) |
| 동전 모두 모으고 골인 | 월드별 장치 해금을 에디터와 연결 |
| 점수 = 죽은 횟수 | 죽은 횟수를 크게 보여주고 친구와 비교 |

## 5. 맵 에디터

칸 단위로 배치하고, 장애물은 경로를 그려서 움직인다. **사용할 수 있는 장치는 캠페인에서 나온 것과 같다.** PC판은 마우스로 클릭·드래그하고, 단축키로 도구를 바꾼다.

### 5.1 배치할 수 있는 것

| 분류 | 종류 |
| --- | --- |
| 지형 | 벽, 바닥, 얼음 바닥, 컨베이어(방향 4가지), 사라지는 바닥 |
| 필수 | 시작점 1개, 골인 지점 1개 이상 |
| 수집 | 동전, 열쇠(색 3가지), 문(열쇠와 같은 색) |
| 장치 | 체크포인트 |
| 장애물 | 동그라미 장애물: 여러 점을 잇는 경로 / 원 회전. 속도 3단계 |
| 꾸미기 | 색 팔레트 선택 (글자·그림은 넣을 수 없음) |

### 5.2 장애물 경로 그리기

이 게임 맵 제작의 핵심이다.

1. 장애물을 놓는다.
2. 이동할 지점을 칸 위에 차례로 찍는다 (최대 8개).
3. "왕복" 또는 "반복 순환" 중 하나를 고른다.
4. 속도와 출발 시점(얼마나 늦게 출발할지)을 정한다.

같은 경로에 장애물을 여러 개 놓고 출발 시점만 다르게 하면 "기차" 같은 패턴이 쉽게 만들어진다.

### 5.3 맵 크기와 제한

| 항목 | 제한 | 이유 |
| --- | --- | --- |
| 맵 크기 | 최대 32 × 18칸 (한 화면) | 원작처럼 한 화면에 다 보여야 패턴을 읽을 수 있다 |
| 장애물 수 | 최대 60개 | 모바일판에서도 느려지지 않게 (맵은 두 판이 공유) |
| 동전 수 | 최대 30개 | |

### 5.4 업로드 규칙: 직접 깨야 올릴 수 있음

슈퍼마리오 메이커와 같은 방식이다. **만든 사람이 직접 한 번 클리어해야 업로드된다.** 절대 못 깨는 맵이 올라오는 것을 막는 가장 확실한 장치다. 만든 사람의 클리어 기록(데스 수, 시간)도 함께 공개된다.

## 6. 맵 공유와 후기

PC판은 자체 서버 없이 **Steam 창작마당(워크숍)**으로 맵을 공유한다. 저장과 구독은 Steam이 맡는다.

### 6.1 단계적 공개 (운영 인력 부족 대응)

운영 인력이 충분하지 않아, **공개 범위를 단계적으로 넓힌다.** 모르는 사람에게 노출되는 공간이 작을수록 관리 부담도 작다.

| 단계 | 공유 방식 | 관리 부담 |
| --- | --- | --- |
| **1단계 (출시, 확정)** | **맵 코드로만 공유.** 창작마당에 "목록에 표시하지 않음"으로 올리고, 코드(링크)를 아는 사람만 플레이 | 낮음. 친구끼리 주고받는 구조 |
| 2단계 | 추천 맵 (운영자가 고른 맵만 공개) | 보통. 주 1회 선별 |
| 3단계 | 창작마당 전체 공개 (인기순, 최신순, 태그별) | 높음. 신고 처리 필요 |

창작마당 항목을 "목록에 표시하지 않음"으로 올리는 방식이 지원되는지는 Steamworks에서 확인이 필요하다. 지원되지 않으면 1단계는 "친구만 보기"로 대신한다.

### 6.2 맵 코드

- 맵마다 짧은 코드가 발급된다 (창작마당 항목 번호를 바탕으로). 친구에게 코드만 보내면 바로 플레이할 수 있다.
- "코드 복사", "Steam 친구 초대" 버튼을 둔다.

### 6.3 후기

맵을 클리어하거나 포기하면 후기를 남길 수 있다. 창작마당의 평가·댓글 기능을 쓰며, 지원 범위는 확인이 필요하다.

| 항목 | 방식 | 비고 |
| --- | --- | --- |
| 좋아요 | 눌러서 표시 | 싫어요는 두지 않는다 (악의적 평가 방지) |
| 체감 난이도 | 쉬움 / 보통 / 어려움 / 지옥 중 하나 | 탭 한 번으로 고르고 바로 다음 맵으로 |
| 한 줄 후기 | 1단계는 **정해진 문구 중 선택** (예: "천재적이다", "악마가 만든 맵", "끝까지 했다") | 자유 입력은 운영 인력이 생긴 뒤에 열기 |

### 6.4 맵 기록과 제작자

- **맵 기록:** Steam 순위표를 맵마다 만들어 최소 데스, 최단 시간 기록 보유자를 보여준다.
- **클리어율이 곧 난이도 표시**다. "클리어율 0.8%" 같은 숫자 자체가 도전 욕구를 자극한다.
- **제작자 프로필:** 내가 만든 맵 목록, 받은 좋아요 합계, 내 맵에서 사람들이 죽은 총 횟수 (제작자에게는 이게 자랑거리다)

## 7. 3~4인 비공개 멀티방

슈퍼마리오 메이커의 친구 멀티 구조를 따른다. 방장이 방을 만들고 **맵 코드 하나를 골라** 친구들과 같은 맵을 동시에 플레이한다. PC판은 **Steam 로비 + 방장 중계**로 추가 서버 없이 운영한다.

### 7.1 방 구조

- 비공개 방만. 방 코드나 Steam 친구 초대로 입장
- 2~4명 (3~4명 권장)
- 맵은 내 맵, 친구가 준 맵 코드, 캠페인 스테이지 중 선택

### 7.2 플레이 방식

| 방식 | 규칙 | 재미 |
| --- | --- | --- |
| **레이스** | 먼저 골인한 사람이 승리 | 서로 경쟁 |
| **협동** | 동전을 나눠 모으고, 한 명이라도 골인하면 모두 클리어 | "너 저쪽 동전 먹어!" 같은 역할 분담 |
| **생존** | 제한 시간 안에 덜 죽은 사람이 승리 | 실수 하나하나에 긴장 |

- 플레이어끼리는 **서로 통과한다** (부딪히지 않음). 원작의 정밀한 조작 감각을 해치지 않기 위해서다.
- 다른 사람은 반투명하게 보이고, 죽는 순간은 똑같이 펑 터진다. "저기서 죽는구나" 하고 배우는 재미도 있다.
- 판이 끝나면 각자 죽은 횟수와 **가장 많이 죽은 장소**를 한 장으로 보여준다.

### 7.3 이 구조가 멀티에 유리한 이유

장애물은 **정해진 경로를 정해진 속도로만** 움직인다. 그래서 모든 플레이어가 시작 시간만 맞추면, 장애물 움직임을 각자 기기에서 똑같이 계산할 수 있다.

- 방장은 **플레이어 위치만** 주고받으면 된다. 실시간 멀티치고는 데이터가 적다.
- 죽음 판정은 각자 PC에서 하므로, 통신이 조금 늦어도 내 플레이는 끊기지 않는다. 다른 사람 위치만 살짝 늦게 보일 뿐이다.
- 같은 원리로, 기록을 올릴 때 **입력 기록을 다시 재생해 검증**할 수 있다. 조작된 기록이 순위에 오르는 것을 막는다.

## 8. 조작과 모바일판과의 관계

### 8.1 PC 조작

| 항목 | 내용 |
| --- | --- |
| 이동 | 방향키 또는 WASD, 게임패드 왼쪽 스틱·방향 패드 |
| 속도 | 항상 일정. 키를 떼면 즉시 정지 (얼음 바닥 제외) |
| 재시작 | R 키로 즉시 처음부터 |
| 에디터 | 마우스 클릭·드래그, 숫자 키로 도구 전환, Ctrl+Z 되돌리기 |

### 8.2 맵은 두 판을 넘나든다

맵 데이터 형식을 같게 만들어, **PC에서 만든 맵을 폰에서도, 폰에서 만든 맵을 PC에서도** 플레이할 수 있게 한다. 단, 조작 방식이 달라 공정하지 않으므로 **기록(최소 데스, 최단 시간)은 플랫폼별로 따로** 집계한다. 모바일판에서 만든 맵은 긴 공유 코드로 오므로, PC판에도 "공유 코드 붙여넣기" 입력칸을 둔다.

## 9. 수익 모델: 유료 판매

Steam에서는 광고 모델이 맞지 않아 유료 판매로 간다. 서버 비용이 없으므로 판매 수익이 그대로 남는다.

| 항목 | 제안 | 이유 |
| --- | --- | --- |
| 기본가 | 5,500~6,600원 | 친구를 멀티방에 부르기 쉬운 박리다매 가격 |
| 추가 캠페인 | 월드 추가 DLC (소액) | 유저 맵이 있어도 공식 고난도 콘텐츠를 원하는 유저용 |
| 무료 체험판 | 월드 1 + 유저 맵 플레이만 | 스트리머와 유저가 먼저 해보고 퍼뜨리게 |

확산 경로는 **스트리머가 고난도 유저 맵에 도전하는 방송**이다. 방송 중 시청자가 맵 코드를 보내고 스트리머가 도전하는 흐름이 자연스럽게 생긴다.

## 14. 남은 결정 & 다음 단계

### 14.1 아직 정하지 않은 것

- [ ] 서버 도입 기준과 시점 (출시 후 반응 지표로 판단)
- [ ] 공개 맵 목록 도입 시점 (운영 인력 확보 후)
- [ ] Steam 창작마당의 "목록에 표시하지 않음" 공개 방식과 평가·댓글 지원 범위 확인
- [ ] 기본가 확정 (5,500원 / 6,600원)
- [ ] 정식 게임 이름 (당분간 가제 유지)

### 14.2 다음 단계

1. **플레이 코어 + 에디터 프로토타입:** 이동 손맛과 경로 그리기가 재밌는지 확인
2. **Steam 창작마당·로비 연동 검증:** 서버 없는 구조가 기획대로 되는지 확인
3. **캠페인 50개 제작:** 우리 에디터로 만들며 에디터 불편한 점 개선
4. **맵 코드 공유 + 멀티방** 추가 후 사내 테스트, 체험판 공개

### 14.3 용어 정리

| 용어 | 뜻 |
